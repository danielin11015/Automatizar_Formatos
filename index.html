Génesis del Proyecto (El Problema vs La Solución)

En la operación diaria de los centros de monitoreo (CCTV y Rastreo GPS), los monitoristas invierten una cantidad desproporcionada de tiempo construyendo reportes en Excel de manera manual. La recolección de evidencias, llenado de checklists y ajuste de imágenes generaba retrasos y cuellos de botella en los tiempos de respuesta del centro.

Este software fue diseñado para actuar como un middleware de alta eficiencia entre el analista humano y el formato final. Integra un motor web de recolección veloz (memoria en portapapeles) y un algoritmo de inyección profunda (COM) que calcula la matemática de aspecto de las imágenes para que encajen al 100% en las plantillas de Excel, sin distorsionar su resolución ni dejar espacios en blanco.

Análisis Estructural (FODA)

Fortalezas (Internas)

Problema: Tiempo excesivo de los analistas armando recuadros manuales en Excel, distorsionando resoluciones.

Solución: Algoritmo de inyección directa (win32com) + Auto-escalado de aspecto para estandarizar evidencias.

Oportunidades (Externas)

Problema: Falta de trazabilidad en los reportes generados y plantillas estáticas difíciles de modificar.

Solución: Arquitectura modular lista para conexión SQL y despliegue rápido de nuevas plantillas de clientes.

Debilidades (Internas)

Problema: El motor de inyección requiere librerías nativas de Microsoft que no corren en servidores Linux.

Solución: Despliegue en entorno Windows Server o ejecución local utilizando un lanzador por lotes (.bat).

Amenazas (Externas)

Problema: Si el cliente final modifica las columnas u hojas de su Excel base, el software no inyectará correctamente.

Solución: Actualización y mantenimiento continuo de las coordenadas de las celdas en el código backend de Python.
